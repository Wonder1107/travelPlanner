# PRD - 动态智能行程引擎 MVP

## 1. 背景与机会
- 现有旅行产品以“静态规划”为主，执行阶段缺乏实时适配。
- 用户核心痛点不是“不会做计划”，而是“计划很快失效”。
- MVP 切入：国内大城市周末 2-3 天游，聚焦高频、短决策链、数据可得场景。

## 2. 目标用户
- 22-35 岁城市年轻用户，偏好周末短途游。
- 强调效率与体验平衡，希望少踩坑并保留探索感。

## 3. 核心问题
- 排队超时、天气变化、疲劳饥饿会快速打断静态行程。
- 用户在执行中缺乏可即时采纳的替代方案。

## 4. MVP 核心能力
- 对话式 onboarding：提取偏好、预算、节奏、避雷项。
- 初始行程生成：RAG 检索 POI + 时间轴排布。
- 动态重规划：监听 weather/crowd/user_status 事件并给出替代方案。
- 解释性日志：展示 Agent 工具调用链与决策理由。

## 5. 不做（MVP 范围外）
- 实际购票支付闭环（仅 mock）。
- 多人协同投票。
- 商业级实时人流数据。

## 6. 成功指标
- 首次行程生成成功率 >= 95%。
- 触发事件后重规划成功率 >= 90%。
- 从提醒到用户采纳建议的转化率（MVP 用交互事件代理）。
